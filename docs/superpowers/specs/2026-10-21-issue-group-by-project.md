# 问答页：按项目分组 —— 需求与设计

**状态：** 需求与设计合一稿，2026-10-21 由 `lane-router/inbox` 起草，由 `lane-router/inbox-impl` 实现。改动有三处：后端加字段、参数和一个只读接口；页面要改；存储结构不改。上线要构建主检出、重启核心。

## 一、来由

用户在问答里问过：问答能不能按项目分开看。design 转给用户两个选择：「一眼看到所有事、但分好组」，或者「每个项目一张独立的板」。用户在 `c49d6f25` 里答：「我觉得我要前者」。

design 给的框架：
- 左栏按项目分组，组可以折叠，组头显示这个项目「待我处理」的条数；
- 加项目筛选，选择记在浏览器里；
- 「待我处理」默认仍然跨项目；
- 每个项目单独一页、用 URL 参数打开，以后按需再加。

细节由本稿定。

## 二、现状

- **左栏。**
  - 有四个状态筛选：待我处理、进行中、全部、已结束。
  - 列表按更新时间从新到旧平铺，每页 100 条，「加载更多议题」翻页。每 5 秒把已加载的页重读一遍。
  - 每条显示标题、lane 地址、时间和徽标。
- **项目名不在问答库里。**
  - 问答库（`issues.sqlite`）的 `issue_thread` 只存 `owner_lane_id`，项目名在核心库的 lane 记录里。
  - 列表里的 `owner` 是 `IssuesService.owner()` 用 `LaneAccess.readLane()` 现查的。`LaneAccessFacts` 只有 `address`，没有 `project`。
- **现在的量**（2026-10-21 从接口读到的）：
  - 共 75 条问答，分布在 9 个项目；
  - `lane-router` 一个项目就有 39 条，其他项目每个 1 到 11 条；
  - 「待我处理」14 条；
  - 再多 25 条，「全部」就要翻页了。

## 三、结论

1. 四个状态筛选下，左栏都按项目分组。组可以折叠，折叠状态记在浏览器里。
2. 组头显示三样：
   - 项目名；
   - 这一组在当前状态筛选下的条数；
   - 这个项目「待我处理」的条数，大于 0 才显示。

   两个数都由后端算，不受翻页影响。
3. **组的先后：** 按组里最新一条的更新时间排，最新的组在最上面；组内照旧从新到旧。这和现在平铺列表「最新的在上面」一致。要找某个项目，用项目筛选。
4. **项目筛选：** 一个下拉框，默认「全部项目」。选了某个项目后，列表只读这个项目的问答，翻页也只在这个项目里翻。选择记在浏览器里。
5. **默认状态：** 「全部项目」、所有组展开，「待我处理」跨项目。
6. **这次不做：** 每个项目单独一页、URL 参数。

## 四、设计

### 后端

1. **owner 带项目名。**
   - `LaneAccessFacts` 加 `project`，由 `router-core.readLane()` 从 lane 记录里取。
   - `IssueOwner` 加 `project: string | null`，lane 已不存在时为 `null`。已归档的 lane 照样带它原来的项目。
   - 列表和详情里的 `owner` 都带这个字段。lane 工具读到的结果会多这一个字段；工具定义和说明不变。
2. **列表接口加可选参数 `project`。** 写法是 `GET /issues/api/threads?filter=…&project=<项目名>`：
   - 值必须符合 lane 地址里单个段的规则（`isAddressSegment`），否则返回 400 `INVALID_INPUT`。
   - 项目名精确匹配，区分大小写，和 lane 记录里的写法一致。
   - 服务层先求出这个项目的 owner lane ID 集合：取问答库里出现过的 `owner_lane_id`，逐个用 `readLane` 查它属于哪个项目。
   - 再在 SQL 里按这个集合筛，比如 `t.owner_lane_id IN (SELECT value FROM json_each(@owners))`。游标翻页不变。集合为空时直接返回空列表。
   - `lane_issue_read` 的列表不开放这个参数，工具 schema 不变。
3. **新的只读接口：** `GET /issues/api/projects?filter=attention|open|closed|all`。
   - **参数：** `filter` 缺省为 `attention`，和列表接口一致。查询里出现别的字段时返回 400。
   - **返回：** `{ result: { items: [{ project, count, attentionCount }] }, actionToken }`。
     - 要和其他 GET 一样带 `actionToken`：页面的 `request()` 每次 GET 都会用返回值覆盖它，少了它，后面的写操作都会失败。
   - **`items`：** 问答库里至少有一条问答的项目，每个项目一项。
     - `count` 是这个项目在给定筛选下的条数，可以是 0。
     - `attentionCount` 是这个项目「待我处理」的条数。口径和 `attention` 筛选完全一样，也算上「lane 已结束、但有用户没读的答复」那种。
     - lane 已不存在的问答，归到 `project: null` 那一项。
   - **顺序：** 按项目名排，不分大小写，和 `listActiveLanes` 一样；`null` 排最后。
   - **实现：**
     - 在 SQL 里按 `owner_lane_id` 分组算出两个数，再在服务层按项目合并。
     - `attention` 的条件和 `listThreads` 用同一段代码，不要复制一份。
   - 这个接口只给页面用，不进 lane 工具。

### 页面

1. **分组。**
   - 列表照旧一页一页读；选了项目时，请求带上 `project`。读到的条目按 `owner.project` 分组。
   - 组的先后：看每组最新一条在平铺列表里的位置。
   - 当前打开的那条不再符合筛选时，照旧留在原位，只是留在它自己的组里。
2. **组头。** 组头是一个按钮，带 `aria-expanded`，显示：
   - 项目名；
   - 「N 条」；
   - 「待我处理 M」，M 大于 0 才显示，徽标用「待我回答」那种醒目的颜色。

   N 取 projects 接口的 `count`，M 取 `attentionCount`。这一组已读到的条数 K 少于 N（后面还有页）时，写成「N 条，已显示 K」。`project` 为 `null` 的组叫「lane 已不存在」。选了单个项目时，组头照样显示。
3. **折叠。**
   - 点组头，折叠或展开这一组。
   - 折叠了哪些项目，存在 `localStorage` 的 `lane-router.issues.collapsed-projects` 里，值是项目名数组。四个状态筛选共用这一份。
   - 读写都包在 try/catch 里；读不到时全部展开。
   - 新问答发出后，页面会跳到新开的那条；它所在的组如果是折叠的，就展开。
4. **项目筛选。**
   - 状态筛选下面放一个下拉框 `#project-filter`。第一项是「全部项目」，后面是 projects 接口给出的项目，不含 `null`。
   - `attentionCount` 大于 0 时，选项写成「lane-router · 待我处理 6」这样。
   - 选择存在 `lane-router.issues.project`。存的项目不在选项里时，按「全部项目」处理。
   - 换项目和换状态筛选一样，从第一页重读。
   - 新问答发出后，页面会跳到「进行中」并打开新的那条。如果当时选着别的项目，新的那条就看不到了；这时把项目筛选切回「全部项目」。
5. **刷新。**
   - 每次读列表时，用同一个 `filter` 一起读 projects 接口。
   - projects 读失败不挡列表：组头只显示已读到的条数，不显示 N 和 M；状态行照旧报错。
6. **窄屏**（宽度 ≤680px）：同样分组。

## 五、范围审计

| 候选面 | 使用者与频率 | 依据 | 处置 |
|---|---|---|---|
| 左栏按项目分组 | 用户，每次看问答 | 用户选了「前者」 | 保留 |
| 组可折叠、记住折叠状态 | 用户 | design 的框架 | 保留 |
| 组头显示「待我处理」数 | 用户 | design 的框架；有翻页时只能由后端算 | 保留 |
| 组头显示这一组的总条数 | 用户 | 有翻页时，一组可能只显示了一部分，要让用户看得出来 | 保留 |
| 项目筛选、记在浏览器 | 用户 | design 的框架；翻页时要按项目在后端筛 | 保留 |
| 每个项目单独一页、URL 参数 | — | design 说以后按需再加 | 不做 |
| 在 lane 工具里按项目筛 | — | 没人提，lane 只看得到自己的问答 | 不做 |
| 新问答的 lane 选择框随项目筛选变化 | — | 没人提 | 不做 |
| 在问答库里存项目名 | — | lane 记录里本来就有，存两份会不一致 | 不做 |

## 六、验收标准

第 1–3 条是 node 组用例（`tests/modules/issues/`），第 4–9 条是 happy-dom 用例，第 10 条是浏览器组（真 Edge），第 11 条是全量。

1. **owner 带项目名。** 列表和详情里的 `owner` 都带 `project`；lane 不存在时为 `null`；已归档的 lane 带它原来的项目。
2. **`project` 参数。**
   - 只返回这个项目的问答。
   - 用 `limit: 1` 一页一页翻时，不会翻到别的项目。
   - 不存在的项目返回空列表；不合规则的值返回 400。
   - 和四个 `filter` 组合，结果都对。
   - `lane_issue_read` 的列表不接受 `project`，schema 会拒绝。
3. **projects 接口。**
   - 四个 `filter` 下的 `count` 都对。
   - 每个项目的 `attentionCount`，等于 `attention` 列表里这个项目的条数；造数据时要有「lane 已结束、但有未读」的一条。
   - 项目按名字不分大小写排序；lane 不存在的归到 `null`，排最后。
   - 返回里带 `actionToken`；有未知查询字段时返回 400。
4. **分组。**
   - 造两个项目的问答，更新时间交错。
   - 组的顺序按每组最新一条排，组内从新到旧。
   - 组头显示 N 和 M；M 为 0 时不显示。
5. **折叠。**
   - 点组头后，组内条目隐藏。
   - 重新加载页面后，这一组仍然折叠；切到别的状态筛选，也仍然折叠。
   - `localStorage` 读写抛错时，全部展开，页面不报错。
6. **项目筛选。**
   - 选项来自 projects 接口。选了以后，列表请求带上 `project`。
   - 重新加载页面后，选择还在。
   - 存的项目不在选项里时，按「全部项目」。
   - 选着别的项目时新开一条问答：发出后项目筛选切回「全部项目」，列表里看得到新的那条，它所在的组是展开的。
7. **一组只显示了一部分。** 这一组已读到的条数 K 少于 N 时，组头写「N 条，已显示 K」。
8. **projects 读失败。** 列表照常显示，组头不显示 N 和 M。
9. **当前打开的那条。** 它不再符合筛选时，留在它自己组里原来的位置。
10. **浏览器组。** 在真 Edge 里：
    - 两个项目的问答分组显示；
    - 折叠一组后重新加载页面，仍然折叠；
    - 选了项目筛选以后，只剩这个项目的问答。
11. 已有的浏览器组和 happy-dom 用例全部通过；`npm run typecheck`、`npm test` 全部通过。

## 七、变异检验

- `attentionCount` 用另写的条件，漏掉「lane 已结束、但有未读」那种 → 3 变红
- `project` 参数没传进 SQL，返回全部 → 2 变红
- 组按项目名字母顺序排，而不是按最新一条 → 4 变红
- 折叠状态不存进 `localStorage` → 5 变红
- projects 接口的返回里不带 `actionToken` → 3 变红
- 项目筛选的选择没带进列表请求 → 6 变红
