# 任务 lane：角色 lane 为有界需求开临时 lane，做完自己归档 —— 需求与设计

**状态：** 需求与设计合一稿，2026-10-21 由 `lane-router/design` 起草；用户在问答 `25c76c8a` 定口径；impl 审稿后修订（第 4.3 节与范围审计按审稿意见收窄：首版不碰 terminal-child）。Vikunja LR-27。实现：`lane-router/impl`（Router：`lane_finish`、完成后归档、拒收）；问答页横幅归 `inbox-impl`；规范改写归 design。依赖 LR-18（开 lane 不再先问用户）已上线。

## 一、问题与结论

用户原话：「小任务就是那种看得清边界的需求。比如我给你提了一个lane-router的小需求，需要稍微澄清几轮就可以做了，我就希望可以开一个新lane去做，特别是你在忙别的或者有并行很多个需求来的时候。做完自己归档肯定是必须的，其实这个有点对标company的那个子task。这个规范要改写一下。」

**结论**：在 subagent 和常驻角色 lane 之间加一层**任务 lane**——为一条边界清楚、但要和用户澄清几轮或要跑一阵的需求临时开的 lane；由收到需求的角色 lane 直接开（不再先问用户），角色说明写明归属与完成条件；**做完交付后自己宣告完成，Router 在它离线后归档它**。首版的「关窗」仍由用户做（看板提示），自动关窗另起小稿先取证。这是 Company 子 task 的对标——接过「有界责任、显式完成、做完清理」，不做账本。

## 二、术语

| 词 | 含义 |
|---|---|
| subagent | Agent 工具开的进程内子代理：一次性、不上看板、不能和用户在问答 / 邮箱里对话。 |
| 任务 lane | 为一条有界需求临时开的 lane：有地址、上看板、能和用户澄清、能被找到和唤醒；角色说明以「任务 lane：」开头；完成即归档。 |
| 角色 lane | 常驻的长期职责 lane（design / impl / inbox …）。 |
| 完成（finished） | 任务 lane 自己宣告的终态：交付已做、邮件与议题已清、不再接活、等归档。 |

## 三、取证

- `archiveLane`（`src/router/router-core.ts:412-428`）对 `restorePresence === "online"` 的 lane 报 `LANE_ONLINE`；**还拒绝有未读邮件的 lane**（`router-core.test.ts`「refuses to archive a lane that still has unread messages」）；只归档离线且无未读的 lane；归档把它的邮件移出工作集、记 `archivedAt`，地址对 `new` 视为空闲。⇒ 「自己归档」要补的缺口有两处：在线时不能归档；归档前不能有未读。
- `terminal-child.ts` 只起 CLI、写状态文件，**不连 Router、收不到 hook**（impl 核实）。「回合结束自动关窗」需要新通路并从外部结束 claude 进程，对会话记录的影响未取证 ⇒ 首版不做。
- Claude 的 websocket 关闭不等于会话结束：`/mcp` 重连、MCP 进程重启都会短暂断开（impl 指出）。Codex 关掉 TUI 后宿主里 thread 仍在，没有对等的「关闭」事件（`restorePresence` 与 `reach` 有意分开）。
- 问答模块给已归档 lane 投递会报 `LANE_UNAVAILABLE`。
- 之前的临时 lane 做法（各 research lane）靠角色说明写「结论交付后归档」，但归档要人跑命令、窗口要人关——清磁盘时翻出 40 多条没人记得干嘛的 lane 和 worktree。
- LR-18 已把「开 lane 要先问用户」拆掉；LR-14 的 set description 让看板能解释一组 lane 是干嘛的。

## 四、设计

### 4.1 三层口径（进规范）

| 层 | 用在 | 开法 | 收尾 |
|---|---|---|---|
| subagent | 不需要和用户对话、不需要被找到的内部活 | Agent 工具 | 自动 |
| **任务 lane** | 边界清楚的需求，但要和用户澄清几轮、或要跑一阵、或要能被找到 / 唤醒 | 收到需求的角色 lane 直接开（4.2） | **交付 → 清邮件与议题 → `lane_finish` → 用户关窗 → Router 归档** |
| 角色 lane | 长期职责 | 用户或角色 lane 开 | 用户决定归档 |

判据：先问「subagent 够不够」——能，就不开 lane。满足「要和用户对话 / 要被找到 / 要跨会话活着 / 要被唤醒」任一条才开任务 lane。

### 4.2 任务 lane 的开法（约定，不加命令）

- 地址 `<project>/<task-slug>`；角色说明**第一句固定**：「任务 lane：为问答 `<议题 id>` 开，归属 `<父 lane 地址>`，完成条件：…，完成即归档。」后面才是任务本身。这一句同时是 4.3 里 `lane_finish` 的准入凭据。
- 父 lane 开它时在**原议题**里说一句「开了 `<地址>` 去做，原因…」；任务 lane 自己的问答归它自己。
- 可以放进父 lane 的 lane set（LR-14 description 写清这组是哪条需求的）。
- 不加 `--task` 之类的新参数：首句约定 + 看板可见就够。

### 4.3 完成与归档（Router 补的小路径）

1. **`lane_finish`**（MCP 工具 + CLI `lane-router-lane finish`；**没有地址参数**，只作用于调用者自己）。准入三条，缺一拒绝并说明原因：
   - 调用者有 active binding；
   - 调用者的角色说明以「任务 lane：」开头（`LANE_NOT_A_TASK_LANE`——角色 lane 误调一次不能把自己永久归档掉）；
   - 调用者的 mailbox 没有未处理（未 ack）邮件，且它名下的问答议题没有 `waiting_user` / `waiting_lane`（`LANE_FINISH_BLOCKED`，错误信息列出还剩什么）——先清干净再完成。
   通过后记 `finished_at = now`（lanes 表新增可空时间戳，schema 11 → 12，按现有迁移写法）。
2. **finish 之后拒收**：对 `finished_at` 非空的 lane，`lane_send`、问答投递、`tell` 一律拒绝，错误 `LANE_FINISHED`，信息里带它角色首句里的原议题与父 lane（「该任务 lane 已完成；追问请到问答 `<议题>` 或联系 `<父 lane>`」）。这样归档前不会再堆出未读信。
3. **归档时机**：
   - Claude 后端：频道关闭后**等 30 秒宽限**，再核 `restorePresence`；仍离线且 `finished_at` 非空且无未读 ⇒ `archiveLane`。宽限是为了 `/mcp` 重连、MCP 重启这类短暂断开——finished 的 lane 若重连上来，仍可读信（只读）和再次 finish，不会被误杀。
   - Codex / zcode / dsh：没有对等的关闭事件，**靠 reconcile**——Router 启动与每次 reconcile 时，凡 `finished_at` 非空、`restorePresence` 非 online、无未读的 lane 归档。Claude 的也在 reconcile 兜底。
   - 若归档前发现仍有未读（理论上只剩 finish 与拒收之间的极小竞态）：不归档，看板标「已完成，有 N 封未读」，下次 reconcile 或收到 ack 后再判。
4. **关窗**：首版**不碰 terminal-child**。finished 且仍在线的 lane，看板和 resume-info 显示「已完成，待关窗」；用户关窗 → 第 3 条归档。自动关窗（terminal-child 订阅 Router、回合结束后退出）另起小稿，先取证「从外部结束 claude 进程对会话记录的影响」再做。
5. **归档后的问答**：任务 lane 名下的议题保留（历史），页面给所属 lane 已归档的议题加一条横幅：「该任务 lane 已完成归档；追问请到父 lane 的议题 `<id>`，或让父 lane 再开一条任务 lane」，回复框禁用（inbox-impl，一小处）。

任务 lane 的收尾顺序固定：交付（按授权提交 / 交集成者 / 在问答里报结果与产物位置）→ 在原议题回一句「完成，产物在…」→ 处理并 ack 剩余邮件、把自己的议题答完或关闭 → `lane_finish` → 不再调任何工具 → 用户关窗。

## 六、验收标准

自动测试：

1. `lane_finish` 的 schema **没有地址参数**（schema 测试）；有 active binding、角色首句为「任务 lane：」、无未处理邮件、名下议题无悬而未决的调用者 → `finished_at` 非空；角色首句不是「任务 lane：」→ `LANE_NOT_A_TASK_LANE`；有未 ack 邮件或有 `waiting_*` 议题 → `LANE_FINISH_BLOCKED` 且信息列出剩余项；无绑定 → 拒绝。
2. finished 的 lane 收 `lane_send` / 问答投递 / `tell` → `LANE_FINISHED`，信息含原议题与父 lane；未 finished 的照常。
3. Claude 频道关闭：finished 的 lane 30 s 后仍离线且无未读 → 归档（`archivedAt` 非空、邮件移出工作集、地址对 `new` 空闲）；30 s 内重连 → 不归档；未 finished 的 lane 频道关闭 → 不归档。
4. reconcile：`finished_at` 非空、`restorePresence` 非 online、无未读的 lane 被归档（含 Codex 后端夹具）；在线的、有未读的不动，后者在快照里标「已完成，有 N 封未读」。
5. finished 且在线的 lane：看板 / resume-info 显示「已完成，待关窗」。
6. 既有 archive、reconcile、lane-access、问答投递测试全过；schema 11 → 12 升级测试通过，旧库升级后数据不变。
7. `npm test`、`npm run typecheck` 全过。

浏览器（issues 组）：

8. 所属 lane 已归档的议题显示横幅与父议题链接，回复框禁用。

真机：

9. 用一条真实小需求走全程：角色 lane 在原议题说明后开任务 lane → 任务 lane 与用户在问答澄清 → 交付 → 原议题回报 → 清邮件、关自己议题 → `lane_finish` → 看板显示「已完成，待关窗」→ 用户关窗 → 30 s 后 `lane-router-lane list-archived` 看到它、看板不再显示；给它发信得到 `LANE_FINISHED`。记 `docs/manual-tests.md`。
10. 规范 `:80 / :83 / :85 / :199` 为三层 + LR-18 口径（已改），工具表含 `lane_finish`；`scripts/kb/kb.py` 检查不报错。

## 七、验证方法与变异检验

- 跑法：`npm test`、`npm run typecheck`；主检出不 build。
- 变异：去掉「任务 lane：」首句准入 → 1 红；去掉未读 / 议题检查 → 1 红；finished 仍收信 → 2 红；去掉 30 s 宽限（关闭立即归档）→ 3「重连不归档」红；关闭不看 `finished_at` 就归档 → 3 红；reconcile 不处理 finished → 4 红；`finished_at` 不持久 → 4 红；归档绕过既有逻辑（不移邮件）→ 3 红。

## 八、边界

- 只加一个自用的 `finish`、一列、一个带宽限的关闭钩子、reconcile 一条规则、一个拒收错误、一条页面横幅；不加父子关系、不加账本、不加 `new` 的参数、**不动 terminal-child**。
- 自动关窗、worktree 自动清理：推迟，各自另起小稿。
- 上线：改了工具目录（`lane_finish` 进 catalog），**要带 `-CodexHost`**；Claude 侧新开 / 恢复会话生效。可与 LR-28「切号后继续」一批。
