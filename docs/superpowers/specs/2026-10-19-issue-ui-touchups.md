# 问答页小修五项：系统记录、列表、在线状态、草稿、改名 —— 需求与设计

**状态：** 需求与设计合一稿，2026-10-19 由 `lane-router/inbox` 起草。用户同意前四项（议题 `e5f33070`），并说「那等你出了方案直接推进到做完就好了吧」。第五项改名来自称呼议题 `986fe0d9`（用户：「那就问答吧」）。稿子写完直接交给 `lane-router/impl`，第五节是验收标准。Vikunja #344。

## 一、问题与结论

| # | 现在 | 改成 |
|---|---|---|
| 1 | 解决问题时写的系统记录，正文里带两个 UUID，按完整条目渲染（`service.ts:88-91`）。真实数据里这类记录占全部条目的 28%。问题面板显示「答复 <uuid>」（`index.html:418`），标题下显示完整的议题 UUID（`:395`） | 系统记录渲染成一行灰色小字，ID 一律显示成 #序号；标题下的议题 ID 只显示前 8 位 |
| 2 | 在「待我处理」里看完或回复一个议题后，它会在下一次轮询时从左栏消失，详情却还开着 | 当前选中的议题在本次浏览期间留在左栏，样式变淡 |
| 3 | 页面不显示 lane 是否在线，用户判断不了「处理未确认」要等多久（`service.ts:223-226` 只给出在役、归档、缺失三种状态） | 列表和详情显示 Router 对 lane 可达性的判断 |
| 4 | 草稿只存在内存里，刷新或离开页面就丢了 | 草稿按议题存在浏览器本地；有正在进行或结果未确定的操作时，离开页面前提醒 |
| 5 | 页面标题、页头和运行看板的入口写的是「议题收件箱」 | 改成「问答」 |

## 二、选型

| 选择 | 采用 | 理由 |
|---|---|---|
| 系统记录按 `service.ts` 的两种固定格式解析，认不出的就把正文里已知的 UUID 换成 #序号后原样显示 | 是 | 不改后端和数据。格式由同一个仓库的 `service.ts` 产生，用测试把两边绑在一起 |
| 议题 ID 显示前 8 位 | 是 | lane 之间就是用前 8 位来指代议题的 |
| 选中的议题留在原来的位置，直到用户选别的议题、切换筛选或刷新页面 | 是 | 位置不动，用户不会以为议题丢了；离开后就按真实筛选结果显示 |
| 在线状态由后端在 `owner` 里多给一个字段 | 是 | 可达性只在 Router 里有（`LaneAccessFacts.reach`、`binding`），页面拿不到 |
| 草稿存 `localStorage`，读写都包 `try/catch` | 是 | 只是图方便，满足 R11「不显示成已保存」；本地存储不可用时退回只存内存 |
| 离开页面前只在「操作进行中或结果未确定」时提醒，**有草稿时不提醒** | 是 | 草稿已经存在本机，离开不会丢；真会丢的只有未确定操作的操作键（刷新后没法用同一个键重试）。这比议题里说的「有草稿也提醒」少一种情况，理由就是草稿已不会丢 |
| `docs/manual-tests.md` 小节名不改 | 是 | 通用仓文档按这个名字引用它（`lane-router-issues.md`、`lane-router.md`） |

## 三、设计

### 3.1 系统记录与 ID

- `kind = event` 的条目渲染成一行灰色小字（不走 Markdown，不显示「记录 · #N · 时间」头，鼠标悬停显示时间）。
- 两种已知格式（`service.ts:88-90`）：
  - `问题 <qid> 已回答（answered）。\n答复 entry ID: <eid>` → 「问题 #<提问条目序号> 已回答（答复 #<答复条目序号>）」
  - `问题 <qid> 无需回答（not_needed）。\n原因：<reason>` → 「问题 #<提问条目序号> 无需回答：<reason>」
  - 其他 event（例如结束议题的记录）：正文原样单行显示，其中能对上的问题 ID 和条目 ID 换成 #序号。
  - 问题 ID → 它的提问条目序号，来自 `detail.questions[].promptEntryId`；条目 ID → 序号，来自已加载的条目。对不上的保持原样。
- 问题面板的「答复 <uuid>」改成「答复 #序号」，对不上的保持原样。
- 标题下的议题 ID 显示前 8 位，`title` 属性里放完整 ID。

### 3.2 选中议题留在列表

- 轮询后的列表里没有当前选中的议题时，把它按上一次渲染时的位置留下，加淡色样式和一个标记「已不在当前筛选」。
- 用户选中别的议题、切换筛选或刷新页面后，按真实结果显示。
- 留下的这一项不算进「加载更多」的游标。

### 3.3 在线状态

后端 `IssueOwner` 增加 `presence`，取值如下：

| 条件 | `presence` | 页面显示 |
|---|---|---|
| lane 缺失或已归档 | `null` | 不显示（沿用「已归档」「已缺失」） |
| 没有 binding | `"offline"` | 离线 |
| `reach.state = "live"` 且 `believedBusy = true` | `"busy"` | 可能在忙 |
| `reach.state = "live"`，其他情况 | `"online"` | 在线 |
| `reach.state = "unconfirmed"` | `"unconfirmed"` | 未确认 |
| `reach.state = "no_channel"` 或 `reach` 为空 | `"offline"` | 离线 |

- 列表项和详情元信息里，在 lane 地址后面显示这个状态。鼠标悬停的说明文字：「Router 的判断，不代表 lane 正在处理你的回复」。
- 只增加字段，现有字段不变；agent 侧 `lane_issue_read` 的返回里也会多出这个字段，这没有问题。

### 3.4 草稿

- 键名 `lane-router.issues.draft.<issueId>`。输入时写入；某个议题的回复区初次渲染、而内存里没有草稿时读出；发送成功后删除。
- 读写失败（隐私模式、存储被禁用）时静默退回只存内存。
- `beforeunload`：任何议题有正在进行或结果未确定的操作时，才请浏览器提示确认离开。

### 3.5 改名

- `src/ui/issues/index.html`：`<title>` 改为「问答 · Lane Router」，`<h1>` 改为「问答」。
- `src/process/dashboard.html:47` 入口文字「议题收件箱」改为「问答」。
- `docs/manual-tests.md` 小节名不改；在小节开头加一句「页面名为『问答』」。

## 五、验收标准

都在 happy-dom 或服务层测试里测，不涉及布局；第 9 条是真机。

1. 系统记录：问题解决（answered）后，那条记录渲染为一行「问题 #<提问序号> 已回答（答复 #<答复序号>）」，页面上不出现这两个 UUID；not_needed 显示原因；结束议题的记录单行显示。用测试同时调用 `service.ts` 写记录和页面渲染，格式一改就会变红。
2. 问题面板显示「答复 #序号」；标题下显示议题 ID 前 8 位，`title` 是完整 ID。
3. 在「待我处理」里，选中的议题因为被回复而不再符合筛选时，下一次轮询后它仍在原来的位置，带淡色和「已不在当前筛选」；选别的议题后它消失；切换筛选后按真实结果显示。
4. `presence`：服务层测试覆盖 3.3 表格的每一行；列表和详情显示对应的文字。
5. 草稿：输入后刷新页面（重新加载脚本），同一议题的回复框里恢复草稿；发送成功后本地草稿被删除；`localStorage` 抛异常时页面照常可用，草稿只存内存。
6. `beforeunload`：有结果未确定的操作时会注册提示；只有草稿时不会。
7. 改名：问答页的 `<title>` 和 `<h1>` 是「问答」；运行看板入口文字是「问答」，链接仍指向 `/issues`。
8. 现有测试不删；断言所测的行为确实变了的（例如 event 条目的渲染、标题下的 ID），可以改，但要在交付说明里逐条列出改了哪条、为什么改。`npm test`、`npm run typecheck` 全部通过。
9. 真机：在跑的 Router 用上新构建后（服务部分要重启 Router 才生效，时机归用户），确认第 1、3、4、7 条的现象，记入 `docs/manual-tests.md`。

## 六、验证方法与变异检验

- 跑法：`npm test`、`npm run typecheck`。主检出不 build；测试一律用临时数据目录，不碰共享 Router。
- 变异检验（每次改坏一处，看对应的测试有没有变红，看完改回）：
  - event 仍按完整条目渲染 → 1 变红
  - `service.ts` 的记录格式改一个字 → 1 变红
  - 选中议题不保留 → 3 变红
  - `believedBusy` 不参与判断 → 4 变红
  - 发送成功后不删本地草稿 → 5 变红
  - 只有草稿时也注册离开提示 → 6 变红

## 七、边界

- 在线状态是 Router 的判断，不代表 lane 正在处理；页面上要写明。
- 草稿只存在当前浏览器里，换浏览器或换机器就没有了。
- `presence` 属于服务部分，要重启共享 Router 才生效；页面部分在读到新页面时生效，但缺少 `presence` 时不显示状态，不报错。
