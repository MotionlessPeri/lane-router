**状态：** 需求与设计合一稿，2026-10-20 由 `lane-router/inbox` 起草。讨论在问答议题 `805a3f1b`「问答支持放文件：你说的『放 file』指哪一种」。

起因是用户在 `lane-router/graph` 的 TUI 里说：「我感觉你说的问答现在不能放file我觉得要支持一下吧」，graph 把这句话转给了 inbox。

条目 #4，用户定下两件都做：「1是不是你调用本机的默认打开就好了 2的话是不是支持我发回复的时候发文件和图片就好了。这里确实有一个痛点，就是我发图片的时候要先截图软件截完保存再把图片拖到tui，很费劲」。

inbox 在条目 #5 补了两处保护，见第二节：能运行的文件不直接打开；上传的文件由 Router 自己保存。

由 `lane-router/inbox-impl` 实现。3.1「点开本机路径」已合进 master（`58b4851`、`f7489f1`）。3.2、3.3 接在[lane 结束问答稿](2026-10-20-issue-lane-close-and-default-publish.md)后面，由同一条 lane 做：两份都要升级问答库、改 `reply` 和页面回复区，先后做就不会互相冲突。

上线：用户在 `205a897d` 第 12 条说「你和graph对一下，把相关需求做完一起部署新版吧」，本稿和 lane 结束问答稿、graph 那边的稿子一起上线。push 等用户说。Vikunja #392。

## 一、问题与结论

现状（`src/ui/issues/index.html:184-191`）：

- 正文用 markdown-it 渲染，`html:false`、`linkify:false`，图片规则关闭。
- markdown-it 默认拒绝 `file:` 链接。就算渲染出来，浏览器也不允许从 http 页面跳到 `file:` 地址。
- 回复框只能输入文字。

2026-10-20 只读扫描了全部 41 条议题、251 条非事件条目：

- lane 写的 164 条里，有 10 条带本机绝对路径，分布在 8 条议题、6 个 lane。内容是目录、计划文档和截图，大多写在行内代码里。
- 用户写的 87 条里没有，因为没有办法放。
- 用户发图给 lane，现在要先用截图工具截图、保存成文件，再拖进 TUI。

结论：

1. **点开路径**：lane 条目里的 Windows 绝对路径渲染成可点的链接，用户点了才由 Router 打开。
   - 文件夹用资源管理器打开。
   - 安全名单里的文件类型用默认程序打开。
   - 其他类型改成在资源管理器里选中，不直接打开。
2. **发文件**：回复框和新问答框里，可以 Ctrl+V 贴截图、拖文件进去，也可以点按钮选文件。
   - Router 把文件存进问答自己的数据目录。
   - lane 收到的信里写着每个文件的保存路径。
   - 页面历史里，图片显示缩略图，其他文件显示文件名。

## 二、选型

| 选择 | 采用 | 理由 |
|---|---|---|
| lane → 用户：点开原路径，不复制文件 | 是 | 用户要「调用本机的默认打开」。文件夹、发布包这类大东西本来就没法复制。lane 什么都不用改，现有写法就能用。代价是临时目录里的文件会被清掉，到时提示「文件已不在」 |
| 默认程序只打开**安全名单**里的类型，其余都在资源管理器里选中 | 是 | 默认程序打开就是 ShellExecute。`.exe`、`.bat`、`.ps1`、`.lnk` 会直接运行；在 Windows 上 `.js`、`.vbs`、`.wsf` 默认交给 Windows Script Host 执行，`.py` 可能被 Python 直接运行。lane 写的文字可能来自别处，黑名单列不全，所以用白名单 |
| 打开路径的入口不绑在问答上（`/local-files/open`） | 是 | graph 的节点 `sources` 也有本地报告路径的需要（graph 来信，样本图 51 个节点里有 45 个）。入口做成通用的，问答页先用。graph 用不用，由 graph 和用户定 |
| 只认行内代码里、或者普通文字里不含空格的 Windows 绝对路径（`X:\…`、`X:/…`），不认相对路径和网络路径 | 是 | 相对路径不知道相对于哪个目录。网络路径（`\\server\…`）和设备路径（`\\?\`、`\\.\`）的风险和语义都不同 |
| 用户 → lane：先上传、再随回复提交编号（两步） | 是 | 现有回复是 JSON，有 1 MB 上限（`http-json.ts:7`），幂等是按载荷摘要做的（`service.ts:249-259`）。先把文件单独上传、拿到编号，回复只多一个 `attachmentIds` 字段，原来的幂等和重试规则不变 |
| 文件存到 `dataRoot/issue-attachments/<附件编号>/<安全文件名>`，上传时就落到最终位置 | 是 | 不用搬文件，没有「库里写了、文件还没搬过去」的中间状态。没被任何回复用上的上传，24 小时后清理 |
| 附件元数据单独建一张表，问答库从 v2 加法升到 v3 | 是 | 沿用 lane 结束问答稿那条只做加法的升级路径 |
| 缩略图只给 png、jpeg、gif、webp | 是 | svg 可能带脚本。其他类型显示文件名，点了走同一个打开入口，安全名单同样生效 |
| lane 给用户发附件（工具参数） | 否 | 用户定的第 1 条是点开路径，不需要 lane 另外上传 |

## 三、设计

### 3.1 点开本机路径

**HTTP 入口** `POST /local-files/open`：

- 路径必须完全一致、不带查询串。
- 动作头 `x-lane-router-action: open-local-path`，沿用 `readPageAction` 的四项检查（来源、动作头、类型、令牌）。
- 请求体 `{ actionToken, path }`，返回 `{ result: { action, path } }`。`action` 的取值：`opened`、`revealed`、`missing`、`refused`。

**服务端判断：**

1. `path` 必须是盘符开头的绝对路径。拒绝 UNC 路径、设备路径、含 NUL 的路径，拒绝时返回 `refused` 和原因。
2. 规范化路径（`path.resolve`），然后查看是否存在。不存在返回 `missing`。
3. 是文件夹：用资源管理器打开，返回 `opened`。
4. 是文件：
   - 扩展名在安全名单里，用默认程序打开，返回 `opened`。
   - 不在名单里，用 `explorer.exe /select,<路径>` 在资源管理器里选中，返回 `revealed`。
5. 启动进程时不经过 shell，参数用数组传，比如 `spawn("explorer.exe", [...])`。默认打开的具体做法由 impl 选，但必须保证路径不会被当成命令解析。

**安全名单（不分大小写）：**

- 图片：`.png .jpg .jpeg .gif .webp .bmp`
- 文本：`.txt .md .log .json .yaml .yml .csv .tsv`
- 文档：`.pdf .html .htm .docx .xlsx .pptx`
- 视频：`.mp4 .mov`

名单写在一处，加类型时只改这一处。代码文件（`.ts`、`.js`、`.py` 等）不在名单里，点了在资源管理器里选中。`.js` 和 `.py` 的默认关联可能直接执行它们。

**页面渲染：**

- markdown-it 渲染后，在 lane 和用户条目的正文里找绝对路径：
  - 行内代码：去掉首尾空白，再去掉末尾的 `:行号` 或 `:行号:列号`，剩下的整段是绝对路径就处理。
  - 普通文字：找不含空格的 `X:\…` 或 `X:/…` 片段，去掉句尾标点。
  - 代码块（`<pre>`）里的不处理，避免干扰复制。
- 找到的路径包成按钮样式的链接，悬停提示「用本机程序打开」。
- 点了调用入口，结果显示在 `#operation-status`：

| `action` | 提示 |
|---|---|
| `opened` | 已打开 |
| `revealed` | 这类文件不直接打开，已在资源管理器里选中它 |
| `missing` | 文件已不在：<路径> |
| `refused` | 不能打开这个路径（原因） |

### 3.2 上传附件

**HTTP 入口** `POST /issues/api/attachments`：

- 动作头 `x-lane-router-action: issues-attach`。
- 来源检查同上。令牌放在请求头 `x-lane-router-token` 里，因为请求体是文件本身。
- `content-type` 为 `application/octet-stream`，文件名用 `x-file-name` 头传，按 URI 编码。
- 单个文件上限 25 MB，边读边计数，超了立即中止，返回 413。
- 返回 `{ result: { attachmentId, fileName, size, mediaType } }`。

**保存：**

- 安全文件名：去掉路径成分和 Windows 不允许的字符，截到 120 个字符；空了就用 `file`。
- `mediaType` 由服务端按文件头识别 png、jpeg、gif、webp 四种，其余记为 `application/octet-stream`。不信任浏览器给的类型。
- 文件写到 `dataRoot/issue-attachments/<附件编号>/<安全文件名>`，同时算 sha256。
- 附件表写一行：

  | 字段 | 内容 |
  |---|---|
  | `id` | 附件编号 |
  | `entry_id` | 先为空，回复提交后填上 |
  | `issue_id` | 先为空，回复提交后填上 |
  | 文件名、`media_type`、`size`、`sha256` | 见上 |
  | `stored_path` | 文件的保存路径 |
  | `created_at` | 上传时间 |

  外键 `(issue_id, entry_id)` 指向条目。

**随回复和新问答提交：**

- `reply` 和 `create` 的输入多一个可选字段 `attachmentIds`，最多 10 个，并且计入操作摘要。
- 在同一个事务里，把这些附件的 `entry_id` 和 `issue_id` 填上。
- 有任何一个编号不存在，或已被别的条目用掉，整个操作拒绝（`INVALID_REFERENCE`），什么都不写。
- 有附件时正文可以为空；正文和附件不能都为空。原来「正文非空」的规则相应放宽，问答库的 CHECK 不改：入库时正文为空，就写「（发送了 N 个文件）」。

**投递正文** 在「用户回复」或「用户的话」后面加一段：

```
附件（N 个，已保存在本机，可直接读取）：
- <文件名>（<大小>）：<stored_path 的绝对路径>
```

**读取：**

- `GET /issues/api/attachments/<编号>`：附件表里有这个编号就给，不管有没有挂上条目。文件从表里记的 `stored_path` 读，不用 URL 拼路径。表里没有（编号不存在或已清理）返回 404。3.3 草稿还原缩略图要用它。编号是随机的，只有页面和收信的 lane 知道，挂没挂上不影响谁能读到。
- 四种图片类型按原类型返回，其余类型带 `content-disposition: attachment`。
- 所有响应都带 `x-content-type-options: nosniff`。
- 议题详情的条目里带上它的附件列表：编号、文件名、大小、类型。

**清理：** Router 启动时，以及之后每 6 小时，删除超过 24 小时还没挂到条目上的附件：先删表里的行，再删目录。删除失败只记日志，下次再试。挂上条目的附件不自动删。

**升级：** 问答库从 v2 升到 v3，只加附件表和它的索引。备份、校验和回退的做法与 v1 升 v2 相同，备份文件叫 `issues.sqlite.v2.bak`。

**实现时补定（2026-10-20，inbox 同意）：**

1. 25 MB 按 25 × 1024 × 1024 字节算，恰好这么大的能传；页面上传前先按大小拦一次。
2. 安全文件名：
   - 去掉末尾的点和空格；
   - `CON`、`NUL`、`COM1` 这类设备名前面加 `_`；
   - 截到 120 个字符时保留扩展名。
3. 清理时，顺带删掉附件目录下没有对应行、并且超过 24 小时的目录。半截上传和删目录失败的残留都在这一步收掉。只删 `issue-attachments` 下一层、名字是附件编号格式的目录。
4. 同一次提交里 `attachmentIds` 有重复，按 `INVALID_INPUT` 拒绝。
5. 只在带了 `attachmentIds` 时把它算进操作摘要，升级前存下的操作重试时摘要不变。

### 3.3 页面：发文件

回复框和新问答框都支持三种添加方式：

- 在输入框里按 Ctrl+V：剪贴板里有图片或文件就上传。剪贴板里只有文字时，照常粘贴文字。
- 把文件拖到输入区。拖过来时整个区域显示一个虚线框。
- 点「添加文件」按钮，打开文件选择框，可以多选。

每个文件一选中就开始上传。输入框下面列出附件：图片显示缩略图，用本地的 object URL；其他显示文件名和大小；每个都有「移除」。

- 上传中显示进度。上传失败显示原因和「重试」。
- 有附件还在上传时，发送按钮不能点。
- 发送时带上 `attachmentIds`。用同一操作重试时，附件编号不变。

草稿：

- 附件编号随草稿存进 localStorage。刷新页面后，附件列表会还原，信息取自后端，缩略图改用 `GET /issues/api/attachments/<编号>`。
- 对应附件已被清理（404）时，从草稿里去掉，并提示一次。

历史里的显示：

- 条目带附件时，正文下面显示附件行。
- 图片缩略图最高 160px，点开后在新标签页里看原图（`GET /issues/api/attachments/<编号>`）。
- 其他文件显示文件名，点了走 3.1 的打开入口，路径是附件的 `stored_path`，安全名单照样生效。

## 五、验收标准

第 1–6 条是 node 组测试，用临时目录，启动程序用替身；第 7–9 条是浏览器组；第 10–11 条是真机。

1. 打开入口的判断：
   - 文件夹打开。
   - 名单内的文件用默认程序打开。
   - `.exe`、`.bat`、`.ps1`、`.js`、`.lnk`、无扩展名都在资源管理器里选中。
   - 不存在的路径返回 `missing`。
   - UNC、设备路径、相对路径返回 `refused`，启动替身一次都不被调用。
   - 启动参数是数组，不含拼接成的命令行。
2. 打开入口的检查：缺来源、动作头不对、令牌不对时都返回 403，启动替身不被调用。
3. 上传：
   - 正常文件落盘，表里一行，sha256 正确。
   - 恰好 25 MB 的文件通过；超过 25 MB 返回 413，不留文件也不留行。
   - 文件名 `..\..\x.bat`、`a:b*c?.png` 都清洗成安全名，最终都落在附件目录内。
   - 伪装成 png 的非图片记为 `application/octet-stream`。
4. 关联：
   - `reply` 和 `create` 带 `attachmentIds` 时，附件挂到新条目上。
   - 编号不存在、已被别的条目用掉、超过 10 个时，整个操作拒绝，什么都不写。
   - 同键重试返回原结果。
   - 只有附件没有正文时，正文写「（发送了 N 个文件）」。
   - 投递正文含每个文件的绝对路径。
5. 读取与清理：
   - 挂上和没挂上的附件都能读取；编号不存在或已清理的返回 404；表里已经没有这一行、文件还在磁盘上（清理删目录失败的情形）时，也返回 404。
   - 图片按原类型返回，其他带 `attachment`。
   - 超过 24 小时还没挂上的附件被清理（行和目录都删掉），挂上的不动。
6. 升级：
   - v2 库升到 v3，有备份，原有数据都在。
   - 再次打开时不升级、不覆盖备份。
   - lane 结束问答稿里的升级测试仍然通过，也就是 v1 库能一路升到 v3。
7. 页面路径链接：
   - 行内代码里的 `E:\a\b.md`、`E:/a/b.md:12` 变成链接，点了用去掉行号的路径调用入口。
   - 代码块里的路径不变。
   - 普通文字里句尾的路径不带上句号。
   - 四种结果的提示正确。
8. 页面发文件：
   - 模拟粘贴图片，附件列表出现缩略图并开始上传。
   - 拖放和选文件也一样。
   - 上传中不能发送，上传失败能重试。
   - 发送后历史里出现附件行，图片有缩略图。
   - 刷新后草稿里的附件还在；附件被清理后提示一次并去掉。
9. 已有的浏览器和 happy-dom 用例全部通过。`npm test`、`npm run typecheck` 全部通过。
10. 真机 TC-ISSUES-FILES-1：用户用 Win+Shift+S 截图，在问答回复框里按 Ctrl+V，发给一个 Claude lane。lane 收到的信里有文件路径，它读出了图片内容并在问答里答复。Codex lane 也做一次。
11. 真机 TC-ISSUES-FILES-2：用户在问答里分别点一个文件夹路径、一个 `.md` 路径和一个 `.ps1` 路径。结果依次是：资源管理器打开文件夹，默认程序打开 md，资源管理器选中 ps1 而不运行它。

## 六、验证方法与变异检验

- 跑法：`npm test`、`npm run typecheck`。主检出不 build；测试用临时数据目录，启动外部程序一律用替身，测试里不真的打开任何东西。
- 变异检验（每次改坏一处，看对应的测试有没有变红，看完改回）：
  - 安全名单里加上 `.ps1` → 1 变红
  - 不拒绝 UNC 路径 → 1 变红
  - 启动时拼接命令行字符串 → 1 变红
  - 打开入口不过 `readPageAction` → 2 变红
  - 不清洗文件名 → 3 变红
  - 超限后仍留下文件 → 3 变红
  - 关联时允许重复使用同一附件 → 4 变红
  - 读取时不查附件表，按编号直接读磁盘 → 5 变红
  - 清理时连挂上的附件一起删 → 5 变红
  - 代码块里的路径也变成链接 → 7 变红
  - 上传中也能发送 → 8 变红

## 七、边界

- 页面不会自己打开任何东西，只在用户点击时打开。名单外的文件类型只在资源管理器里选中。
- 不复制 lane 写的路径指向的文件，不认相对路径和网络路径。
- 不给 lane 新增上传工具。
- 已挂上条目的附件不自动删除，磁盘占用归用户手动处理；交付说明里写出附件目录的位置。
- 上线要重启共享 Router（`scripts/restart-router.ps1`，由 design 执行），和 lane 结束问答稿一起带 `-CodexHost`。用户已同意相关需求做完后一起上线，push 归用户。
