# 图资源接入技术设计草案

状态：用户已认可第一版流程、长写锁和图模型，并于 2026-10-19 允许基本删除、要求直接开始。按本稿及[实施计划](../plans/2026-10-19-graph-resources.md)实施和本地验证，不在本 lane 部署或重启共享 Router。需求依据见[图资源接入需求](2026-10-18-graph-resource-requirements.md)。

## 1. 结构与边界

采用 Router 同进程内置的独立图资源模块。通信核心管理 lane 身份与通信；图模块管理图的身份、内容、保存和长写锁。agent 工具与只读网页使用同一图服务，不各自维护一份图。

图资源引用为 `{ type: "graph", id }`，ID 独立生成，不包含 owner lane。工具每次显式传图 ID，不增加持久的 lane 与资源绑定表，也不在会话里维护隐式的“当前图”。多个 lane 可以使用相同引用，一个 lane 可以交替操作多份图。

| 部件 | 职责与依赖 |
|---|---|
| `src/modules/graphs/` | 数据校验、文档命令、服务、SQLite 存储、图工具、HTTP 及 CLI 适配 |
| `src/ui/graphs/` | React Flow 查看页面、分组投影与布局；读取服务返回的图 |
| `src/application/` | 复用现有 `ToolCatalog`，显式组合通信、议题和图工具 |
| `src/process/` | 打开模块、连接现有身份端口及 HTTP、关闭资源；不写图业务规则 |

图服务只依赖自己的存储和已有 `LaneAccess` 身份接口，不依赖议题服务、UI、HTTP 或 core 数据库。只装配通信的产品保持原有行为；图模块由独立产品入口显式装配，不把 `issues:false` 隐式改成“另启图模块”。不增加持久插件配置、动态加载或新服务进程。

候选方案已在需求稿第 5 节比较：独立图服务增加运行管理；agent 直接编辑文件会绕过统一锁规则。本稿选择同进程独立模块，实际存储在模块内部，供后续其他类型用相同宿主方式提供各自工具；当前不抽通用资源平台。

## 2. 图文档与数据归属

图内容以一个文档保存。节点、关系与分组都有稳定 ID，ID 在所属文档内唯一；节点与分组 ID 也不得相互冲突，方便可见投影。图标题可以重复，打开与修改始终按图 ID 定位。

| 内容 | 首版字段与含义 |
|---|---|
| 图 | `schemaVersion: 1`、`title`、可选 `description`、`nodes`、`edges`、`groups` |
| 节点 | `id`、`label`；可选 `summary`、`description`、`kind`、`tags`、`sources`、`groupId`；未指定分组时在全景直接可见 |
| 关系 | `id`、`source`、`target`、`type`，可选 `description`；端点引用本图节点 |
| 分组 | `id`、`label`；可选 `summary`、`description`、`parentId`、`color`；父引用只能指向本图分组 |
| 来源 | 节点 `sources` 中的 `{title,url}`，只接受 HTTP/HTTPS 地址，页面按文本和普通外链展示 |

一个节点最多属于一个导航分组，标签和跨组关系表达交叉。分组可嵌套，父关系不得循环；普通知识关系可以成环。首版不接受关系端点缺失、重复 ID 或自环。分组关系由 `parentId` / `groupId` 表达，不再另外保存一套“主题包含”业务边。

`schemaVersion` 只表示文档格式，不参与写入冲突检查；`updatedAt` 只供展示和排序。本稿不引入图内容版本号或自动合并。

| 数据 | 权威位置 | 派生或临时状态 |
|---|---|---|
| 标题、节点、真实关系、分组与来源 | 图模块保存的文档 | agent 读取结果、网页详情和画布派生 |
| 持锁者、获锁凭据 | 图模块存储 | 工具与管理命令显示当前事实 |
| 节点坐标、相机、展开、选择与当前分组 | 当前查看页面 | 页面内调整，不写回资源，不进入持锁流程 |
| 收起后的聚合边、导航包含线 | 当前可见图投影 | 每次从文档和查看状态重建，不反写成真实关系 |

默认收起顶层分组；无分组节点直接可见。展开分组保留父级摘要，显示其直接子组与节点，跨组关系按可见祖先聚合；双击进入局部图，面包屑返回。搜索可定位隐藏节点并展开其祖先。聚合、搜索与避让沿用原型已验证的行为，去掉固定三层约束。节点短描述与完整侧栏说明保持原有体验。

## 3. 保存与事务

模块独占 `dataRoot/graphs.sqlite`，沿用当前 `better-sqlite3`，单独维护格式迁移，不改 `router.sqlite` 或 `issues.sqlite`。不直接复用议题存储类或共享业务表。

| 表 | 内容与约束 |
|---|---|
| `graph_resource` | 图 ID、文档 JSON、创建与更新时间；没有 owner lane 字段 |
| `graph_lock` | 图 ID 为主键并引用本库资源；保存 `lockId`、持锁者稳定 `laneId`、获锁时间 |
| `graph_operation` | 保存写操作的调用方范围、`operationKey`、操作种类、请求摘要和结果；防止结果未知时重试产生第二次修改 |
| `graph_schema_version` | 图模块自己的存储迁移版本 |

一次批量修改在短事务内重新验证当前调用方、锁和完整候选文档，整体保存文档与操作结果。失败则全部回滚。长时间持有的是 `graph_lock` 记录，不是长数据库事务；读取返回某次完整提交的图，不暴露半批修改。

读取已有库或格式失败时不覆盖、不重新生成空库；图入口明确返回 `GRAPHS_UNAVAILABLE`，通信与议题继续按自身规则工作。数据库打开、事务、关闭及备份采用项目现有 SQLite 约定，包括 WAL 一致快照；不能只复制 core 文件便声称备份了图。

`operationKey` 是本稿提出的重试处理方案：每次新的创建、修改、获锁或释放使用新键；同一操作结果未知时重试复用原键。键范围绑定实际调用 lane 的稳定 ID，不允许模型另填调用身份。同键同内容返回原操作凭据和执行结果，同键异内容返回 `OPERATION_CONFLICT`。只有成功的写入保存去重结果，持锁冲突或校验失败不占用操作键。

去重结果只保存资源 ID、相关锁 ID及原操作提交摘要，不保存整份图快照。创建或申请锁重放时单独读取当前文档和当前锁状态，明确区分原操作与现在的事实，不能将最初空图或旧快照冒充最新内容。记录属于内部去重，不提供历史浏览、回滚或版本管理产品功能。

## 4. 长写锁规则

1. agent 调用图工具时由宿主通过 `LaneAccess` 解析当前有效绑定。工具参数没有可自选的调用 lane、binding 或 generation；只传实际资源引用和操作内容。
2. 无锁时，申请在短事务内生成新的随机 `lockId`，记录持锁者稳定 lane ID，并返回当前文档。该返回满足“拿到锁后读取最新内容”。
3. 同一 lane 当前有效会话再次申请已持有的锁，返回同一获锁凭据和最新文档，不轮换凭据。其他 lane 收到 `GRAPH_LOCKED` 及持锁者可读信息；不抢占、不阻塞 RPC、不建立后台等待队列。等待意味着稍后重试，而非用户必须放弃本次任务。
4. 修改和释放都检查当前有效调用身份、持锁者 lane ID 与 `lockId`。在开启同步事务前紧邻复核调用身份，中间不插入 `await`；锁和操作键在同一事务内检查。不同 lane 即使知道公开锁 ID也不能通过工具写入。
5. 锁无租期、无续租，不因 turn 结束、网络暂断或网页关闭而释放。Router 重启保留锁记录；同一 lane 当前有效会话可重新申请以取得原锁和最新文档。
6. 同一 lane 的会话恢复或代际轮换保留其稳定身份，因此新有效绑定可以继续本 lane 的锁；旧绑定继续调用会被 core 身份端口拒绝。lane 归档、地址复用不移交旧锁，用户可按下节手动解除。图内容不因此删除。
7. 主动释放删除当前匹配的锁。后续申请生成不同 `lockId`，旧凭据无效。发生强制解锁时，在途修改与解锁按图库事务提交顺序决定：先提交的内容保留，解锁先提交则旧凭据写入失败。

操作键重试不重新执行副作用。若原获锁已完成但锁后来失效，重试返回“原获锁操作已执行、当前凭据已失效”，不能静默拿回新锁。原修改已提交但锁后来失效时，同键重试只返回原修改结果，标为重放，不再写图或恢复锁。当前会话身份校验仍然适用。

## 5. 用户强制解锁

查看页可显示持锁者及获锁时间，继续只读。强制解锁放在本机管理 CLI：

```text
lane-router-lane graph force-unlock --id <graphId> --expected-lock <lockId>
```

它向同一 Router 的本机管理入口提交图 ID 与用户看到的锁 ID；只有当前锁仍匹配才解除。若用户查看后锁已换人，返回 `LOCK_CHANGED` 并要求重看，不能解掉后来者的新锁。无锁时返回“当前未锁定”。成功只解除锁，不回滚已保存内容。

此操作不加入 agent 图工具的动作列表，不增加图页写按钮；agent 只能在用户明确要求异常接管时代执行管理命令。本机可信进程本来可以调用本地管理入口，这不是区分“用户亲手”与“agent 代操作”的技术沙箱。

管理 HTTP 拟为 `POST /graphs/admin/:graphId/force-unlock`，复用现有本机管理入口的 loopback、拒绝浏览器 Origin 和 JSON 校验，不增加远程接口、账号或可选目标 lane。命令通过 Router discovery 查当前实例，不直改 SQLite、不固定端口。此管理入口与下面的只读网页 API 分开。

## 6. agent 工具与兼容 CLI

拟定为四项图类型工具；通过同一份 schema 导出 MCP、Codex 动态工具及兼容 CLI，不新增独立 MCP server。

| 工具 | 参数与结果 |
|---|---|
| `lane_graph_create` | `operationKey`、`title`、可选 `description`；原子创建空图并取得写锁，返回图引用、`lockId`、当前空文档及查看地址 |
| `lane_graph_read` | 不带 ID时列表，可加 `query` 按标题筛选及 `afterId` / `limit` 分页；带 `graphId` 时读取完整图、锁状态及查看地址 |
| `lane_graph_lock` | `graphId`、`action: acquire/release`、`operationKey`；释放另带 `lockId`，申请成功返回锁及最新文档 |
| `lane_graph_apply` | `graphId`、`lockId`、`operationKey`、`changes`；返回保存后的图摘要和查看地址 |

列表只返回资源摘要，不返回所有图正文；按 ID稳定排序，默认 50、最大 200 条。不同 lane 使用同一资源集合，不按创建者隐藏图；本轮不增加项目归属或权限配置。普通读取不需要持锁，也不会更改“当前图”。

批量修改 `changes` 提供 `set_graph`（标题与说明）、`upsert_group`、`upsert_node`、`upsert_edge`。各操作使用文档中的稳定 ID，更新字段由严格 schema 定义；未提供字段保持，显式 `null` 清除可空分组引用。批内按顺序修改候选文档，最后一次性验证引用和保存，因此可以在同一批创建分组、节点并连线。

批量修改另提供 `delete_node` 和 `delete_edge`，按 ID显式删除已有实体。节点被删除后仍有关系引用它时，最终校验使整批回滚；调用者应在同批显式删除或改指这些边，不隐式级联。首版不提供分组或整个图删除、全图替换、执行脚本和任意元数据写入。

沿用现有 1 MiB JSON 请求上限，不新增容量配置或另一套图大小门槛。超过既有请求限制明确拒绝，保持原图，不截断数据或自动拆成多个资源。首版采用完整读取，验收基于经典样例规模和无分组样例，不承诺无限规模图或大图性能；如后续实际规模需要局部查询，再按具体场景设计。

旧 Codex 会话使用 `lane-router-lane graph <create|read|lock|apply> --json-file <path>`，复用议题 CLI 的身份来源和同一工具调用模式。身份来自当前进程的 `CODEX_THREAD_ID`；缺失或当前会话未绑定时明确拒绝。新会话的动态工具和常规 MCP 走宿主已有装配；受限 DSH/Native Host 白名单不在本轮修改。不会为取得工具而自动轮换或重开 lane。

## 7. 只读查看网页与构建

| 路径 | 行为 |
|---|---|
| `GET /graphs/:graphId` | 返回同一个查看页，页面按路径中的 ID读取资源 |
| `GET /graphs/api/:graphId` | 返回完整图、可显示的锁状态与更新时间；`Cache-Control: no-store` |
| `GET /graphs/assets/...` | 只读取构建产物清单内的脚本、样式和字体，未知路径 404；不拼接任意文件路径 |

没有网页创建、图内容修改或讨论接口；刷新按钮重读后端。网页可在当前页面临时拖动节点、调整布局和展开阈值，关闭后丢弃查看状态；不加载演示编辑器、本地草稿或撤销历史，也不将其向后端上传。取消选择沿用空白点击、Esc 和详情 ×。

UI 沿用原型的 React、React Flow 与 D3-Force 版本，保留 React Flow 署名。只迁入只读画布、详情及相关投影/布局能力，不引入 G6、Reagraph 或 Three 依赖。图中标题和说明按文本显示，来源只接受 HTTP/HTTPS，不解释资源内容为指令或 HTML。

主仓现有 `tsc` 只编译 `.ts`，复制脚本只带 HTML；它们不会构建 React 页面。图前端使用单独的 TypeScript 与 Vite 构建边界，不由后端 `tsc` 收集其入口；产物纳入现有生产构建并由 Router 提供，最终运行不依赖 5177 开发服务。前端不修改原有后台 UI，不将 React 改造扩散到议题或运行看板；依赖安装、构建及静态产物验证留在实施阶段的隔离工作树，不在本设计轮执行。

图服务返回稳定 ID与相对查看路径；工具适配器使用当前 Router origin 生成查看 URL。ID 是资源引用，临时本机端口不是资源身份。Router 端口变化后从 lane 重新读取取得新地址，不承诺历史绝对 URL跨实例始终可用。

## 8. 错误、失败与恢复

| 情况 | 结果与后续动作 |
|---|---|
| 图不存在或引用错误 | `GRAPH_NOT_FOUND` / `INVALID_GRAPH`，不创建替代资源 |
| 其他 lane 持锁 | `GRAPH_LOCKED`，返回持锁者；保留当前请求意图，稍后重新申请 |
| 无锁、旧锁 ID或别人的锁 | `LOCK_INVALID`，不修改任何内容 |
| 绑定失效、归档或地址复用 | 沿用 core 身份错误；不靠参数或同名地址移交写权限 |
| 任一批内修改或最终图校验失败 | 整批回滚，明确错误及对应实体 ID，锁仍由原 lane 持有 |
| SQLite 保存失败 | 不确认保存成功，原图和操作结果事务回滚；用户仍可查看之前保存内容 |
| 保存成功但工具结果丢失 | 使用同一操作键取得原结果，不能重做副作用；同时报告当前锁是否有效 |
| Router 在持锁期间重启 | 保存图与锁仍在；同 lane 有效会话可取回锁并重读，其余 lane 等待或由用户接管 |
| 持锁者长期不可用 | 用户查看状态，使用匹配的锁 ID强制解锁；不靠超时抢占 |
| 图模块无法打开 | 图相关入口明确不可用；不清空库，不把通信或议题报为同样失败 |

`updatedAt`、传输成功、lane 在线和写锁状态互不替代；只有图事务提交成功才报告本次修改已保存。批量调用之间不形成额外事务或编辑草稿：一轮中已经保存的批次对读者可见，释放锁不再另做“发布”。

## 9. 验证与交付边界

先用临时库和隔离 Router fixture 验证业务，再接静态前端。关键验证包括：

- 普通无分组图、嵌套分组、跨组边聚合、普通关系环、分组循环和悬挂引用。
- 两条 lane 同时申请只成功一条；未持锁、旧凭据、其他持有者和旧 binding 均不能写；同 lane 恢复可接续。
- 创建即持锁、批内增组增点连边、失败整批回滚；读取从未见到部分批次。
- 图、锁与去重结果跨进程重启恢复；创建/保存响应丢失后同键重试不重复，异内容报冲突，失效获锁重试不重新抢锁。
- 用户带旧预期锁 ID强解失败；真实同时提交的写入和强解遵守事务顺序。
- 五项通信工具及议题行为不变；显式装配与未装配场景、多个入口的 schema 与身份来源一致；不扩大外部 Host 工具集合。
- 独立图服务测试不导入 UI或 HTTP；core 不导入图模块；网页不导入存储。
- 生产构建的脚本、样式、字体实际落入 `dist`；只用生产 Router 打开图，关闭 5177 开发服务仍可浏览。
- 真实浏览器检查普通图、分组导航、避让、搜索、详情、空白/Esc 取消选择、刷新后端结果及只读边界；真实客户端确认至少一条普通 lane 完成创建、获锁、读写、释放和网页查看。

用户已要求按此方案实施和本地验证；不把原型测试或议题模块测试转作图接入已通过的证据。实际客户端/模型验收与外部部署状态分别报告；共享 Router 部署和重启交外部维护对话，不由本 lane 执行。

## 10. 方案范围审计

基线为需求稿 R1—R7。以下是本次要审阅的具体技术选择；操作键与管理入口需要连同其代价明确确认，不因写入设计稿就成为用户原始需求。

| 候选 | 消费者与频率 | 需求依据 | 删除后果 | 既有替代 | 处置 | 关闭条件 |
|---|---|---|---|---|---|---|
| 图服务及独立 SQLite 文件 | lane 和网页，正常路径 | 明确：R1、R2、R5；独立文件为拟定实现 | 无共享保存与事务 | 演示 JSON、本地草稿缺统一写入口 | 保留服务；文件选择待本稿确认 | — |
