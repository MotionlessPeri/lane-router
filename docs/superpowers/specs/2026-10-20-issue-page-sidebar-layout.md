# 问答页改成左侧边栏布局 —— 需求与设计

**状态：** 需求与设计合一稿，2026-10-20 由 `lane-router/inbox` 起草。用户在问答议题 `c107ea05` 提出「页头太大」，要做成「类似 agent 那种格式，比如 gpt 或者 dsh，左侧边栏是对话」「选项卡也放到左侧边栏里面贴着左边」；（条目 #5）；inbox 回了示意图（条目 #6）；用户回复「对的。然后现在左右都是留白的，中间就很挤。你要是明白了开始推进？」（条目 #8），之后又说「ok，你直接推进到部署验收好了」。稿子写完直接交给 `lane-router/impl`，做完后接着提交、上线、做真机验收，中间不再停下来等用户确认。第五节是验收标准。Vikunja #366。

## 一、问题与结论

2026-10-19 上线后实测：窗口 1280×800 时，讨论历史框只有 235px 高（`docs/manual-tests.md` TC-ISSUES-SCROLL-1 的最后验证）。两栏框上方依次是页头、「问答」大标题、说明文字、筛选行和「已刷新」状态行，一共约 265px（`src/ui/issues/index.html:126-138`）；整页还有最宽 1280px 的居中限制（`:21`）。

结论（宽屏，≥681px）：改成 ChatGPT 那种两块布局。

- **左侧边栏**：贴窗口左边，从顶到底占满高度。从上到下依次是：「问答」和「运行看板」入口；四个筛选选项卡和刷新；议题列表（单独滚动）。
- **右侧主区**：占满剩余宽度和高度。标题栏在顶，回复区在底，中间的讨论历史滚动。内容铺满主区，只留正常边距，不再设最大宽度。
- 去掉横贯顶部的页头、说明文字和整页 1280px 的宽度限制。用户说过「现在左右都是留白的，中间就很挤」，所以新布局里两侧都不能再留白。

窄屏（≤680px）保持上下排列、整页滚动。

## 二、选型

| 选择 | 采用 | 理由 |
|---|---|---|
| 侧边栏宽 `clamp(240px, 24vw, 320px)`，贴左边、占满高度 | 是 | 用户要求「贴着左边」；1280 宽时约 307px，四个选项卡一行放得下 |
| 筛选做成侧边栏里的一行选项卡，不做成竖排 | 是 | 竖排四项要多占约 100px 高度，挤掉议题列表 |
| 右侧内容铺满主区，不设最大宽度，左右各留 32px 边距 | 是 | 用户明确不要两侧留白。inbox 起初在示意图里写了「正文居中、最宽约 860px」，在宽屏上会重新留出白边，已撤回 |
| 说明文字改成「问答」标题的悬停提示 | 是 | 阅读时用不上，又占一行 |
| 「问答」仍然是 `<h1>`，放在侧边栏顶部 | 是 | 页面语义和现有测试（标题是「问答」）不变 |
| 「已刷新 hh:mm:ss」改成选项卡下面一行小字，刷新按钮放在同一行 | 是 | 状态还看得到，但只占一行 |
| 侧边栏可拖动改宽、可收起 | 否 | 这次不需要，以后有需要再加 |

## 三、设计

### 3.1 结构（宽屏）

```
body (flex 行，高 100vh)
├─ aside.sidebar（贴左、满高、右边一条分隔线、面板底色）
│   ├─ 顶部行：<h1>问答</h1>（悬停显示原说明文字）· 运行看板链接
│   ├─ #filters：待我处理 / 进行中 / 全部 / 已结束（一行）
│   ├─ 状态行：#list-status 小字 · 刷新按钮
│   └─ .list-panel：#thread-list 和「加载更多议题」（单独滚动）
└─ main.conversation（满高，flex 列）
    ├─ #markdown-status（只在出错时显示）
    └─ #issue-detail：标题栏 / 历史区（滚动）/ 回复区，三块都铺满主区宽度，左右各留 32px 边距
```

- 现有的元素 ID 和 `data-*` 属性都保留（`#filters`、`#refresh`、`#list-status`、`#thread-list`、`#issue-detail`、`#history-region`、`#compose-region` 等），脚本逻辑不变，只改结构和 CSS。
- 去掉 `<header>`、`<p class="muted">` 说明文字、`main { max-width: 1280px }`。原页头里的那句「议题从 TUI 发起 · 本页可直接继续讨论」并进 `<h1>` 的悬停提示。
- 高度下限：整体最矮 420px，比这还矮时整页可以滚（沿用滚动稿的下限）。

### 3.2 窄屏（≤680px）

上下排列、整页滚动，和现在一样：侧边栏的内容（标题、选项卡、列表）排在上面，议题详情在下面。侧边栏不贴边、不占满高度，列表不单独滚动。

### 3.3 不变的行为

滚动稿（定位、分隔线、跟随、增量渲染）、已读（有焦点且末尾进入视野）、小修五项（保留项、presence、草稿等）的行为全都不变。它们的浏览器测试里依赖页面几何的断言，按新布局改数值，不改意图。

- 已读稿的「矮窗口」用例，要的是「页面本身在滚动、历史区下半截在窗口外」这个场景。新布局去掉了顶部区域，1280×440 已经不会整页滚动，所以要把视口高度降到新下限以下（例如 1280×360），让这个场景重新出现。

## 五、验收标准

第 1–5 条在真实浏览器里测（沿用现有的 Edge/Playwright 写法，放在 browser 组）；第 7 条是真机。

1. 1280×800：侧边栏左边在 x=0、顶边在 y=0，高度等于视口，宽度在 240–320px 之间；文档的 `scrollHeight` 等于视口高度。
2. 1280×800、打开一个长议题：历史区 `clientHeight ≥ 500`；标题栏顶边在视口顶部附近（≤ 24px）；「发送回复」按钮完整在视口内。
3. 侧边栏里依次能找到：`<h1>问答</h1>`、运行看板链接（`href="/dashboard"`）、四个筛选选项卡、刷新按钮、议题列表；议题数超过侧边栏高度时，列表在侧边栏里单独滚动，文档高度不变。
4. 1920×1000：标题栏、历史区和回复区的宽度，等于主区宽度减去左右边距（误差 ≤ 2px）；侧边栏右边缘到主区内容之间、主区内容到窗口右边缘之间，都只有边距，没有额外的留白。
5. 375×800：仍然整页滚动；侧边栏内容排在议题详情上面；历史区没有自己的滚动条。
6. 滚动稿、已读稿、小修稿已有的浏览器用例和 happy-dom 用例全部通过。几何断言按新布局改的，在交付说明里逐条列出改了什么、为什么。已读稿的矮窗口用例改用新下限以下的高度，并在交付时说明用的是多少。`npm test`、`npm run typecheck` 全部通过。
7. 真机：在跑的 Router 读到新页面之后（只改页面，主检出 build 后即可，不需要重启 Router；时机归用户），在本机浏览器打开问答，确认第 1–3 条的现象，记入 `docs/manual-tests.md`。

## 六、验证方法与变异检验

- 跑法：`npm test`、`npm run typecheck`。主检出不 build；测试一律用临时数据目录，不碰共享 Router。
- 变异检验（每次改坏一处，看对应的测试有没有变红，看完改回）：
  - 恢复顶部页头和标题区 → 1、2 变红
  - 侧边栏不占满高度（例如去掉 `height: 100vh`）→ 1 变红
  - 选项卡留在侧边栏外面 → 3 变红
  - 列表不单独滚动 → 3 变红
  - 给主区内容加一个最大宽度（例如 `max-width: 860px; margin: 0 auto`）→ 4 变红
  - 窄屏也用侧边栏布局 → 5 变红

## 七、边界

- 只改页面布局，不改任何交互逻辑和数据。
- 侧边栏宽度不能拖动，也不能收起。
- 页面上线只需要主检出 build（在跑的 Router 按请求读页面），不需要重启 Router；build 的时机归用户。
