# 本机统一账号切换

## 用户流程和边界

用户已批准制作独立后台和账号页：完成一次官方 ChatGPT 授权后，选择一个保存的账号，同时切换 Company 与 Router 管理的 Codex lane。现有回合自然结束，原有会话和任务绑定保留。页面只有两边都核实成功才显示完成；离线、等待和失败分别显示。实现及验证在独立工作树，当前运行账号不变，部署交外部运行对话。

本机同一 Windows 用户及其进程是信任边界。网页和普通网络来源不持有模型凭据；不支持远程访问、多用户权限管理、任意独立 CLI 进程或模型供应商迁移。用户已批准的“一次授权、统一切换”包括必要的后台进程、账号存储、运行端接入和切换页面。

## 设计

`lane-router-accounts` 是独立的回环 HTTP 服务，退出不停止 Router 或 Company。每个账号使用后台专属的 `CODEX_HOME`，官方 Codex `app-server` 完成 `account/login/start` 的浏览器授权，以 `cli_auth_credentials_store=keyring` 强制使用系统凭据库。后台通过官方 `getAuthStatus` 获取短期访问令牌，不读取、复制或自行刷新 refresh token。每个账号同时只有一个后台拥有的登录进程和一条串行请求队列。

页面只获得账号名称、脱敏邮箱、工作区标识的短指纹、套餐、运行端状态和操作进度。官方授权 URL 由后台校验域名后直接交本机浏览器，不经页面或日志。账号元数据和后台连接文件保存在仓库外的受限目录；Windows 使用当前用户及 SYSTEM 的 NTFS 权限，其他平台使用 `0700`/`0600`。模型凭据只存在官方凭据库和后端内存。错误对外只使用固定错误码，不能回传底层 RPC 异常或请求内容。

两个运行端通过受限连接文件中的随机连接凭据建立长期 WebSocket。浏览器没有此凭据，升级请求带 `Origin` 时一律拒绝。接入模块调用官方实验接口 `account/login/start(type=chatgptAuthTokens)`，并持续处理 `account/chatgptAuthTokens/refresh`。刷新按账号身份合并并串行执行，只允许刷新原用户与工作区，不能趁刷新切换账号。运行端不获得 refresh token。现有 Codex 主进程不需要因普通账号切换而重启。

切换操作只允许同时进行一个。先验证目标授权，再要求两个运行端停止接纳新的模型请求，等待已接纳请求和所有已加载会话的回合结束，确认没有会自动产生新回合的活动目标或已排队回合，最后逐一应用目标令牌并读回身份。阻止新请求必须覆盖后台通知、Company 队列及 TUI 请求，不能只读一次 idle。Company 尚未 dispatch 的任务保留，换号后继续消费；只有已 dispatch 或效果未明的操作需要等待。Codex 内部队列非空或存在活动 goal 时，准备明确失败并恢复接纳，页面提示待其完成后重试，避免门阻止队列消费却等待其清空。等待普通回合期间允许取消，尚未应用时恢复原运行状态。开始应用后发生部分失败则明确列出结果，保留目标和未完成状态供重连/重试，不谎称事务回滚，也不重放用户输入。

接入模块在后台掉线后保留现有回合，暂停新模型请求；重连后先核对期望账号再开放。账号服务重启不自动认为上一次切换已完成。已注册的两个运行端必须都在线并完成核对，才可显示“全部已同步”。独立 UI 服务不依赖有效模型账号。外部部署人员负责设置连接文件路径并安装启动入口。

`AccountSwitchGate` 负责接纳边界和等待空闲；`AccountConsumer` 负责后台连接和令牌刷新；Company 作者将它接入其队列和现有长期 app-server 客户端。不会使用临时诊断连接充当刷新拥有者，也不会为换号创建新会话。Router 代码仅增加同类接入，不改问题看板。

Company 在 claim 前取得同一 Host gate 的作用域准入，使用私有顶层 `accountAdmissionToken` 贯通后续短 WebSocket 的 resume 和最终 RPC。Host 验证并剥除该字段；作用域结束或出现未知效果后不能继续使用。这样已 claim 的任务可以在切换等待期间完成派发，未 claim 的本地 FIFO 留待释放后继续。

部分应用后重新尝试的等待不能取消并开放两端。重连时按运行端实际身份寻找保存的账号，允许旧回合继续刷新；应用进行中或其效果未知时禁止身份重绑和刷新。认证 RPC 超时不等于远端取消。只有确认运行进程替换才清除未知效果，旧进程的迟到响应不能修改新进程的门状态。重新授权不调用可能撤销远端授权的 logout，旧不活动 keyring 条目保留。

## 验收

- 全新授权只打开官方登录页面，任何 HTTP 响应、UI 存储和普通错误均不包含访问或刷新令牌。
- 两个模拟运行端 A 切 B，忙碌时等待；并发新请求无法穿过切换边界；取消等待不改账号。
- 部分应用失败、后台或运行端断线及重启均可观察，不显示全部完成；重试后读回一致才成功。
- 刷新请求合并；错误账号、错误工作区、旧操作及失效授权被拒绝，页面给出重新授权提示。
- 实际 Codex 0.163.0 与 Company 0.161.0 在隔离目录及合成令牌下，同一 thread 先用 A，再用 B，401 后以 B 的刷新令牌重试成功。已有私有探针证明请求序列 `A/B/B/refreshed-B`，正式验收将其变成可重复测试入口。
- 真实账号授权及两边接入后的最终验收由外部部署对话执行，保留原 thread、员工及任务绑定。仅合成测试不能声称已上线可用。
