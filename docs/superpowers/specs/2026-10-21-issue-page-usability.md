# 第一批

## 一、问答 id 变成能跳转的链接

### 1.1 现状

- lane 和用户在正文里提别的问答时，写的是完整 id，或者是前 8 位（如 `205a897d`）。页面只把它当普通文字显示，用户看不出是哪一条，也点不过去。
- 问答页不读地址栏参数（`index.html` 里没有 `location` / `history`），所以不能用链接直接打开某一条。
- 正文里的十六进制串还可能是别的东西：信件 ID、条目 ID、提交号，或者恰好是 8 位十六进制的普通词。只看长得像不像来认，会认错。

### 1.2 结论

1. **认哪些：** 正文里的完整 UUID，以及独立成词的 8 位十六进制串，都算候选。
2. **谁说了算：** 只有后端确认它确实是某条问答，才变成链接；不是的照旧当文字。
3. **链接显示成什么：** 链接文字保留正文原来写的，后面用浅色小字跟上标题。
4. **点了怎样：**
   - 普通点击：在本页打开那一条，地址栏变成 `?issue=<完整 id>`，浏览器的「后退」能回到原来那条。
   - 按着 Ctrl / Shift / ⌘ 点，或用中键点：浏览器照常在新标签打开。
5. **深链：** `/issues?issue=<完整 id 或前 8 位>` 能直接打开那一条。
6. **地址栏跟着走：** 在列表里点选某条时，地址栏也更新，刷新页面后还停在这一条。

### 1.3 设计

**后端：新加只读接口 `GET /issues/api/resolve?refs=<逗号分隔>`。**
- **参数：**
  - `refs` 里每一项是完整 UUID（带连字符，大小写都收），或者正好 8 位十六进制。
  - 最多 100 项。
  - 格式不对、超过 100 项、有未知查询字段，都返回 400 `INVALID_INPUT`。
- **返回：**
  - `{ result: { items: [{ ref, id, title, status, ownerAddress }] }, actionToken }`。
  - 和其他 GET 一样带 `actionToken`，原因同按项目分组稿：页面的 `request()` 每次 GET 都会用返回值覆盖它。
- **匹配规则：**
  - 完整 UUID 按 id 精确匹配；
  - 8 位前缀匹配 id 的开头；
  - 只返回唯一匹配的，没匹配上或匹配到不止一条，都不出现在 `items` 里。
  - `ownerAddress` 取 `owner.address`，lane 不存在时为 null。
- **实现：** 在 `IssuesService` 加 `resolve(refs)`，在 store 里一项一项查。完整 id 用 `id = ?`，前缀用 `id LIKE ? || '%'`；8 位十六进制里没有 `%` 和 `_`，不用转义。
- **lane 工具：** 不开放这个接口，工具 schema 不变。

**页面：认候选。**
- 在 `entryBody` 里做，接在 `linkLocalPaths` 后面，lane 写的和用户写的都处理。
- 范围和本机路径一样：
  - 普通文字和行内代码里的认；
  - 代码块（`pre`）、已有的链接、已经是本机路径链接的不认。
- 匹配用的正则：
  - 完整 UUID：`/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}/gi`；
  - 8 位：`/(?<![0-9a-zA-Z-])[0-9a-f]{8}(?![0-9a-zA-Z-])/gi`，前后都不能紧挨着字母、数字或连字符。
- 行内代码：整个 code 的文字（去掉首尾空白）正好是一个候选时才认。
- 认出来的候选先包成 `span.issue-ref-candidate`，`data-ref` 写小写后的原文。

**页面：查和缓存。**
- 一次渲染里没查过的候选，合起来发一次 resolve 请求。
- 结果存在页面内存的 `Map` 里：查到的存结果，没查到的存 `null`。同一个 ref 在这一页里只查一次。
- 请求失败不缓存，下次渲染再查；页面不报错，候选照旧显示成文字。

**页面：升级成链接。**
- 查到的候选换成 `a.issue-ref`：
  - `href` 是 `?issue=<完整 id>`；
  - `title` 是「标题 · 所属 lane · 进行中 / 已结束」；
  - 链接文字是原文。
- 链接后面跟 `span.issue-ref-title`，内容是「（标题）」：
  - 标题超过 24 个字就截断，加「…」；
  - 样式用 `--muted` 色、小一号字。
- 行内代码里的候选：照本机路径的做法，用链接把 code 包起来。

**页面：点击和地址栏。**
- **普通左键点击：**
  - `preventDefault()`；
  - `history.pushState({ issue: id }, "", "?issue=" + id)`；
  - `selectIssue(id)`；
  - 如果当时在「进度」标签，`selectIssue` 本来就会切回「问答」。
- **带修饰键的点击：** 不拦，交给浏览器。
- **在列表里点选：** 用 `history.replaceState` 把地址栏改成这一条，不加历史记录。
- **新问答：** 打开新问答的写作界面时，用 `replaceState` 去掉 `issue` 参数。
- **`popstate`：**
  - 地址里有 `issue` 就打开那一条；
  - 没有就回到空的详情区；
  - 这一步不再 push 新的历史记录。

**页面：深链。**
- 页面启动时读 `issue` 参数：
  - 完整 UUID：直接 `selectIssue`。
  - 8 位：先走 resolve。查到了就 `selectIssue`，再用 `replaceState` 把地址栏换成完整 id；没查到就在详情区显示「没找到问答 `<原文>`」。
  - 其他格式：不处理。
- 打开的那条不在当前筛选的列表里也没关系：详情照常显示，列表不变。

## 二、标题旁的短 id 加复制按钮

- 详情的标题栏下面那行（`detail-meta`）已经显示前 8 位，悬停能看到完整 id（`index.html` 里的 `.issue-id`）。在它后面加一个小按钮「复制」，点了把**完整 id** 写进剪贴板。
- 照代码块复制按钮（`addCopyButton`）的做法：用窗口自己的 `navigator.clipboard`。成功后按钮显示「已复制」，直到下次打开这条才变回来，不用计时器。失败显示「复制失败」。

## 三、回复框把手：往上拖加高

### 3.1 现状

宽屏时回复区钉在窗口底部（`#compose-region`），回复框 `#reply-body` 用浏览器自带的 `resize: vertical`，把手在右下角。可是回复区的底边是固定的，往下拖时实际是上边缘往上走：用户拖的是右下角，动的是上边。

### 3.2 结论

- **宽屏（>680px）：**
  - 去掉浏览器自带的把手，在回复框上边缘放一条横向把手，往上拖加高，往下拖减低；
  - 拖出来的高度记在这个浏览器里，每条问答都用这个高度。
- **窄屏（≤680px）：** 整页滚动，回复框不钉底，自带的右下角把手本来就顺手，保持不变，也不显示新把手。

### 3.3 设计

- **把手：**
  - 在回复表单里、`#reply-body` 正上方，放一个 `div.reply-handle`：
    - 高 8px、整行宽，中间画一条短横线；
    - `cursor: row-resize`。
  - 无障碍属性：`role="separator"`、`aria-orientation="horizontal"`、`aria-label="调整回复框高度"`、`tabindex="0"`。
- **拖动：**
  - 用 pointer 事件：`pointerdown` 时 `setPointerCapture`，记下起点 y 和当时的高度；`pointermove` 时，新高度 = 起始高度 + (起点 y − 当前 y)。
  - 高度有上下限：
    - 下限是两行，也就是现有的 `min-height`；
    - 上限是窗口高度的 60%。
- **键盘：** 把手获得焦点时，↑ 加高一行（`1.65em`，按回复框的计算字号换算成 px），↓ 减低一行。
- **复位：** 双击把手，回到默认高度。
- **和现有展开规则的关系：**
  - 现在回复框有两个预设高度：平时两行，用起来时 `#compose[data-expanded="true"]` 撑到六行。
  - 用户拖过以后，回复框加上 `data-sized="user"`，用 `style.height` 定高；展开规则要改成只对没有 `data-sized` 的回复框生效。
  - 双击复位时，去掉 `data-sized` 和 `style.height`，并清掉存储。
- **存储：**
  - 键名 `lane-router.issues.reply-height`，值是 px 整数。
  - 读写都包在 try/catch 里；读不到或值不合理（不是正整数），就按没拖过处理。
  - 建回复表单时读出来用上，超过当时的上限就压到上限。
- **样式：**
  - 宽屏下 `#reply-body` 设 `resize: none`；窄屏的媒体查询里保留 `resize: vertical`，并把 `.reply-handle` 设为 `display: none`。
  - 新问答的正文框 `#new-body` 不钉底，不改。

## 第一批验收标准

第 1 条是 node 组用例，第 2–6 条是 happy-dom，第 7 条是浏览器组（真 Edge），第 8 条是全量。

1. **resolve 接口：**
   - 完整 UUID、8 位前缀都能查到，返回标题、状态和所属 lane。
   - 不存在的不出现在结果里。
   - 有歧义的也不出现：造两条前 8 位相同的问答，测试里固定 id。
   - 格式不对、超过 100 项、有未知查询字段，返回 400。
   - 返回里带 `actionToken`。
   - lane 工具的 schema 没有变。
2. **认候选：** 一条 lane 写的 Markdown 正文、一条用户写的纯文本，里面各放这几样：
   - 一个完整 UUID、一个已有问答的 8 位前缀：变成链接，后面跟着「（标题）」；
   - 一个不是问答的 8 位十六进制、代码块里的一个 UUID：保持文字。
   - 一次渲染只发一次 resolve 请求。同一个 ref 再次渲染时不再请求。请求失败时页面不报错，下次渲染会重查。
3. **点击：**
   - 普通点击：打开目标那一条，地址栏是 `?issue=<完整 id>`，历史记录多一条；
   - 触发 `popstate` 时回到原来那条；
   - Ctrl 点击不被拦下；
   - 在列表里点选某条：用 `replaceState`，历史记录条数不变。
4. **深链：**
   - 带 `?issue=<完整 id>` 加载，打开那一条；
   - 带 `?issue=<前 8 位>` 加载，打开那一条，地址栏换成完整 id；
   - 带一个不存在的 8 位，详情区显示「没找到问答 …」。
5. **复制：** 点「复制」，剪贴板里是完整 id，按钮显示「已复制」；剪贴板不可用时显示「复制失败」。
6. **把手：**
   - 宽屏下往上拖 100px，回复框加高 100px，有上下限；
   - 刷新页面、换一条问答，高度都还在；
   - 双击复位，存储也清掉；
   - ↑/↓ 各调一行；
   - 存储抛错或存了不合理的值，页面照常工作，用默认高度；
   - 窄屏下把手隐藏，回复框仍是 `resize: vertical`；
   - 拖过以后再触发展开，高度不变。
7. **浏览器组：** 在真 Edge 里，用一个真 Router：
   - 一条问答的正文里写另一条的前 8 位，点它，详情切过去，地址栏变了，按后退能回来；
   - 拖把手往上，回复框变高，发送按钮的位置不变。
8. 已有的浏览器组和 happy-dom 用例全部通过；`npm run typecheck`、`npm test` 全部通过。

## 第一批变异检验

- 不经后端确认、把所有 8 位十六进制都变成链接 → 2 红
- 代码块里的也认 → 2 红
- 点击不调 `preventDefault` 或不 `pushState` → 3 红
- 不读 `issue` 参数 → 4 红
- 复制的是前 8 位而不是完整 id → 5 红
- 拖动方向反了（往上拖变矮）→ 6、7 红
- 不存高度 → 6 红
- resolve 接口不带 `actionToken` → 1 红

## 四、渲染 lane 写的 mermaid 图

design 答应用户的口径：
- 只画 lane 写的；用户写的仍是纯文本。
- 渲染库随页面从本地提供，不走外网，钉一个具体版本号。
- `securityLevel: 'strict'`。
- 画不出来就显示源码，并写一行原因。
- 大图可以点开放大。

**设计要点：**
- **依赖：**
  - `package.json` 加 `mermaid`，写死具体版本，不带 `^`，选发布满两周以上的稳定版，交付时写明。
  - 照 markdown-it 的做法提供：新路由 `GET /issues/assets/mermaid.js`，用 `createRequire(...).resolve("mermaid/dist/mermaid.min.js")` 读文件返回。
- **按需加载：** 某条 lane 写的正文里第一次出现 mermaid 代码块时，才往页面里插这个脚本。整页只插一次。没有图的页面不加载。
- **认哪些块：** 只认 lane 写的 Markdown 正文里，信息串（去掉首尾空白、不分大小写）正好是 `mermaid` 的代码块。
- **初始化：** `mermaid.initialize({ startOnLoad: false, securityLevel: "strict", theme: <跟着页面的深浅色> })`。
- **渲染：**
  - 用 `mermaid.render(<唯一 id>, 源码)` 拿到 SVG，放进 `div.mermaid-diagram`，替换原来的 `pre`。
  - 下面放一个 `details`（「源码」），里面是原来的代码块，带复制按钮。
- **画不出来：** 语法错，或者脚本没加载成功，就保留原来的代码块，在它上面写一行 warning：「图没画出来：<原因>」。
- **放大：** 点图，打开一个覆盖全页的 `dialog`，按原始大小显示 SVG，可以滚动。按 Esc 或点 dialog 外面关掉。
- **轮询：** 5 秒轮询时条目不重建，所以不会反复重画，这一点要用例守住。
- **上线：**
  - 加了依赖，所以部署时先在主检出里 `npm install`。不用 `npm ci`，原因见共享树的老规矩：在跑的 Router 占着 better-sqlite3 的 `.node`。
  - 然后 build，重启核心。
- **后续：** 通用仓 `techniques/lane-router-issues.md` 加一句「问答页会画 lane 写的 mermaid 代码块」，由 inbox 上线后改。

## 五、`LR-n` 链到 Vikunja 卡

**vikunja/main 的回答（2026-10-21）：**
- 原来网页只能按任务 id 打开（`/tasks/<id>`）。按「项目 + 编号」查只有 API 能做，要令牌，不能当链接用。
- 它在定制版里加了一个网页跳转，说当天上线：`<Vikunja 根地址>/projects/<项目>/tasks/by-index/<编号>`。
  - `<项目>` 写项目简称 `LR` 也行；
  - 跳转页会替换掉自己那条历史记录；
  - 没登录先去登录；
  - 卡挪过项目的，旧卡号也能找到；
  - 找不到卡时页面上有提示。
- 它建议直接用卡号前缀 `LR` 拼链接，不要把 `LR` 映射成 12：链接和网页上显示的卡号同源，以后加别的项目只是多认一个前缀。约定里会写上「项目简称不要改」。

**设计：**
- **认哪些：**
  - 只认 `LR-` 加数字，独立成词：`/(?<![\w-])LR-(\d+)(?![\w-])/g`。
  - 不用 `[A-Z]+-\d+`，它会误伤 `UTF-8`、`SHA-256`。
  - 范围和本机路径一样：普通文字和行内代码，代码块不认。
- **链接：**
  - 地址是 `<origin>/projects/LR/tasks/by-index/<n>`；
  - `target="_blank"`、`rel="noopener noreferrer"`；
  - `title` 是「在 Vikunja 里打开 LR-<n>」。
- **origin 从哪来：**
  - 取 `/dashboard/state` 里 `progressBoard.url` 的 origin。
  - 页面启动时用单独的 `fetch` 读一次，不经过 `request()`，原因同进度标签页。和进度标签页共用这一次读取的结果。
  - 读到 `null` 或读失败，`LR-n` 就不变链接，照旧显示文字。之后进度标签页重读成功时，把已经渲染的条目补成链接，补的方式和问答引用一样。
- **不读 Vikunja 的 API，不配令牌。**

## 六、lane 地址链到左栏筛选

- 正文里的 lane 地址（`<项目>/<lane>`，两段都符合地址规则），以及详情标题栏下的所属 lane，都变成可点的。条件是后端确认这个地址存在，归档的也算。
- 点了以后，左栏加一个「只看 `<地址>` ✕」的筛选标签：
  - 项目筛选自动设成这个地址的项目；
  - 列表请求带上 `lane=<地址>`，只列这个地址名下所有 lane ID（现在的和归档的）的问答；
  - 点 ✕ 或换项目时去掉这个筛选。
  - 这个筛选不存进浏览器。
- **后端：**
  - 列表接口加可选参数 `lane`；
  - resolve 接口加 `lanes` 一类，返回地址存在与否和所属项目；
  - 做法和按项目分组的 `project` 一样，从 `ownerLaneIds` 里用 `readLane` 过滤。
- lane 工具不开放。

## 第二批验收标准

第 1、5 条是 node 组用例，第 2、4、6 条是 happy-dom，第 3 条是浏览器组（真 Edge），第 7 条是全量。

1. **mermaid 依赖与路由：**
   - `package.json` 里 `mermaid` 的版本是具体版本号，不带 `^` 或 `~`；
   - `GET /issues/assets/mermaid.js` 返回打包好的文件，`content-type` 是 JavaScript。
2. **mermaid 页面（happy-dom，`window.mermaid` 用替身）：**
   - lane 写的正文里有两个 mermaid 块：脚本只插一次，每块都画出来，下面有「源码」；
   - 用户写的正文里有 mermaid 块：保持文字；
   - 渲染抛错：保留代码块，上面有一行「图没画出来：…」；
   - 脚本加载失败：同样处理；
   - 5 秒轮询以后：不重画。
3. **mermaid 真渲染（真 Edge）：**
   - 一张流程图画成 SVG；
   - 节点文字里写 `<img src=x onerror=...>`：不执行，用页面上的全局标记来核对；
   - 点图打开放大层，按 Esc 关掉。
4. **`LR-n`：**
   - 文字和行内代码里的 `LR-39` 变成指向 `<origin>/projects/LR/tasks/by-index/39` 的新标签页链接；
   - `UTF-8`、`SHA-256`、`XLR-3`、`LR-39a`、代码块里的 `LR-39` 都不变；
   - 没配置看板时不变链接；之后配置读到了，已渲染的条目补成链接；
   - 读 `/dashboard/state` 不覆盖页面的 `actionToken`。
5. **lane 筛选（后端）：**
   - 列表带 `lane=<地址>` 时，只列这个地址名下的问答，包括同地址已归档的 lane；
   - 地址格式不对返回 400；
   - 和 `filter`、`project` 能组合；
   - resolve 接口对存在的地址（归档的也算）返回 `lanes` 一项，不存在的不返回；
   - lane 工具的 schema 不变。
6. **lane 筛选（页面）：**
   - 正文里存在的 lane 地址，以及详情里的所属 lane，都可以点；点了出现「只看 … ✕」，项目筛选也跟着变，列表请求带 `lane`；
   - 点 ✕ 或换项目，筛选去掉；
   - 刷新页面后筛选不在；
   - 不存在的地址不能点。
7. 全量 `npm test`、`npm run typecheck` 通过。

# 第三批

## 七、提交号做成链接

**impl 的回答（2026-10-21）：**
- 每条 binding 记着会话的工作目录 `cwd`，lifecycle hook 报上来时写入。`RouterStateStore.latestProjectCwd(project)` 能按项目取最近一次的 cwd，已归档的 lane 也查得到。
- 要注意三点：
  - cwd 可能是 worktree，不过 worktree 和主检出共用对象库，查提交号哪边都行；
  - 从没报过 lifecycle 的老 binding，cwd 是 null；
  - Router 里没有「仓库」和「远端」的概念。
- 建议不放进 `LaneAccessFacts`，在问答模块的 ports 里加一个小接口，由 `main.ts` 装配。不用改存储，约半天。

**设计：**
- **Router 侧（impl）：** 问答模块的 ports 加 `repoForLane(laneId) → { root, webUrl } | null`。
  - 先取 cwd：活跃 binding 的 cwd，没有就用 `latestProjectCwd(project)`。
  - 在 cwd 下跑 `git rev-parse --show-toplevel` 和 `git remote get-url origin`，结果按目录缓存。
  - 把远端改写成网页地址：`git@github.com:o/r.git` 和 `https://github.com/o/r(.git)` 都改成 `https://github.com/o/r`。其他远端返回 `webUrl: null`。
  - 拿不到 cwd，或者不是 git 仓库，返回 null。
- **后端（inbox-impl）：** resolve 接口加 `commits` 一类。
  - 请求时多带一个 `issue=<id>`。
  - 正文里 7 到 40 位、不是问答 id 的十六进制串，到这条问答所属 lane 的仓库里核实。
  - 用 `git cat-file --batch-check` 核实，一批只起一个进程。
  - 是提交、而且有 `webUrl`，才返回 `{ ref, sha, url: <webUrl>/commit/<完整 sha> }`。
  - 别的仓库的提交号查不到，就不链。比如 lane-router 的问答里提到通用规范仓的提交号，那个仓库不是这条问答的。
- **页面：**
  - 认候选的范围和问答 id 一样；
  - 链接用新标签页打开，`title` 写完整 sha。
- **公司项目：** 远端是公司 GitLab 或者没有远端，首版都返回 `webUrl: null`，不链。以后要链 GitLab，再加一条改写规则。

第三批的验收照第二批的写法，等 impl 的接口做好以后补进本稿。至少要有这几条：
- 是提交才链，查不到不链；
- 别的仓库的提交号不链；
- 远端不是 GitHub 不链；
- 一批只起一个 git 进程。
